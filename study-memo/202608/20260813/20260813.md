- Carをこんな感じで書き換える
  - いろんな型に対応できるようにした感じ？
  - 意味はあんまりないとのこと。なぜなら型はString, String, Intでどうせ使うから。（あんまり変わらないから）
- 

```
data Car = Car { company :: String
               , model :: String
               , year :: Int
               } deriving (Show)
----
data Car a b c = Car { company :: a
               , model :: b
               , year :: c
               } deriving (Show)
```

- １個目のCar定義ならこんな関数が書ける
  - なんか2個目だとNGになった。多分型が多相的だからダメなのかな？？

```
tellCar :: Car -> String
tellCar (Car {company = c, model = m, year = y}) = "This " ++ c ++ " " ++ m ++ " was made in " ++ show y
---
ghci> let stang = Car {company="Ford", model="Mustang", year=1967}
ghci> tellCar stang
"This Ford Mustang was made in 1967"
```

- 2個目のCar定義だとこうしなきゃいけない模様。型定義が複雑になった
- 実際に使うとyearにStringも入れられる感じ
- しかし、実用上はCar String String Intを使うことが圧倒的に多い。だからCarを多相的にしても労力に見合わない。。
  - 普通、型引数を使うのはデータ型の値コンストラクタに収納された型が、データ型自体の動作にそこまで重要な影響を与えないとき
  - 例えば数のリストの合計を求めたくなったら数のリストを引数にとる総和関数を後から作ればいい

```
tellCar :: (Show a) => Car String String a -> String
tellCar (Car {company = c, model = m, year = y}) = "This " ++ c ++ " " ++ m ++ " was made in " ++ show y
----
ghci> tellCar (Car "Ford" "Mustang" 1967)
"This Ford Mustang was made in 1967"
ghci> tellCar (Car "Ford" "Mustang" "nineteen sixty seven")
"This Ford Mustang was made in \"nineteen sixty seven\""
ghci> :t Car "Ford" "Mustang" 1967
Car "Ford" "Mustang" 1967 :: Num c => Car String String c
ghci> :t Car "Ford" "Mustang" "nineteen sixty seven"
Car "Ford" "Mustang" "nineteen sixty seven"
  :: Car String String String
```

- Data.MapモジュールのMap k vは多相型だけど、これは型引数が大活躍できてる
- だけど、こう型クラス制約を加える選択肢もあった。
- しかし、Haskellにはデータ宣言には決して型クラス制約をつけないという激つよコーディング規約がある
  - なぜか？メリットがない＋必要ない箇所にまで型クラス制約を書く必要があるから
  - → 例えばListだとその関数や連想リストにも`(Ord k) =>`をつける必要が出てきてしまう
- 結論：データ宣言には型クラス制約をつけるな

```
data (Ord k) => Map k v = ...
```
