# Haskell学びメモ 20260714

- foldlはスタックオーバーフローエラーが発生する場合にある
  - Haskellはアキュムレータの計算を実際には行わず、その次でも評価せず評価を先延ばしにする
  - 新しい計算で前の計算結果を参照するかもしれないのでメモリ上に保持し続ける
  - で、どんどんメモリを消費する先延ばしにした計算が積み上がっていき、スタックオーバーフローエラーを起こす
- 本では100万だったけど、もうちょいいけたっぽい

```
ghci> foldl (+) 0 (replicate 100 1)
100
ghci> foldl (+) 0 (replicate 1000000 1)
1000000
ghci> foldl (+) 0 (replicate 10000000 1)
10000000
ghci> foldl (+) 0 (replicate 100000000 1)
*** Exception: stack overflow
```

- Haskellがどう`foldl (+) 0 [1,2,3]`を評価するのか↓
- 先延ばしにした計算による大きなスタックがまず構築されて、空リスト到達後に計算が開始される
  - そのためでかいリストではスタックオーバーフローになる

```
foldl (+) 0 [1,2,3] =
foldl (+) (0 + 1) [2,3] = 
foldl (+) ((0 + 1) + 2) [3] =
foldl (+) (((0 + 1) + 2) + 3) [] =
(((0 + 1) + 2) + 3) =
(1 + 2) + 3 =
3 + 3 =
6
```

- あーあ計算を先延ばしにしない、こんなfoldl'があればな〜〜
  - → なんとある！
  - Data.List.foldl'

```
foldl' (+) 0 [1,2,3] =
foldl' (+) 1 [2,3] =
foldl' (+) 3 [3] =
foldl' (+) 6 [] =
6
```

- エラーになってたやつもfoldl'だとできた！
- foldl1にもfoldl1'ってのがある

```
ghci> import Data.List
ghci> foldl' (+) 0 (replicate 100000000 1)
100000000
```
