# Haskell学びメモ 20260902

- 順序づけ可能なOrdも自動導出可能
  - どうやるんだ？メンバの合計の長さ？とか？
  - → 同じ型の値を2つ比較した時、異なる値コンストラクタから作られたなら先に定義されているほうが小さいとする
  - Boolだと定義がこうだと考えると分かり易い。つまりTrueのが後だから順序はTrueが後ろ。
    - 他の言語だと0, 1みたいな感じのイメージもあるからこれはそんな気がする

```
data Bool = False | True deriving (Ord)
----
ghci> True `compare` False
GT
ghci> True > False
True
ghci> True < False
False
```

-  2つの値が同じ値コンストラクタなら等しくなる。フィールドがあればフィールド同士が比較される
  - なおその場合はフィールドの型もOrdに属している必要がある
- Maybe aデータ型だとNothingがJustの前に定義されてるので、Nothingは常にJust somethingより小さい
- なおJust (*3) > Just (*2)みたいなことはできない模様。`*3`とかは関数の型なので

```
ghci> Nothing < Just 100
True
ghci> Nothing > Just (-49999)
False
ghci> Just 3 `compare` Just 2
GT
ghci> Just 100 > Just 50
True
ghci> Just (*3) > Just (*2)

<interactive>:9:11: error: [GHC-39999]
    • No instance for ‘Ord (Integer -> Integer)’
        arising from a use of ‘>’
        (maybe you haven't applied a function to enough arguments?)
    • In the expression: Just (* 3) > Just (* 2)
      In an equation for ‘it’: it = Just (* 3) > Just (* 2)
```
