# Haskell学びメモ 20260810

- 値コンストラクタは引数を取って新しい値を生み出す
- 型コンストラクタは引数を取って新しい型を生み出す
- 下の例でaが型引数で、Maybeが型コンストラクタ
  - Maybeは引数があって初めて型を生み出し型となれる
  - なるほど、型の上位存在というか値における関数みたいな？

```
data Maybe a = Nothing | Just a
```

- 明示的に型を型引数として渡したければ型の世界で行う必要がある。
  - `::`の右側がHaskellでの型の世界となる
- Maybe以前にも型コンストラクタを使っていた。その正体はリスト！
  - `[]`単体では型になれず、StringやIntと合わせることで型になれる。確かに
- 具体型：型引数を1つも取らない型か、あるいは型引数を取るけれどもそれが全て埋まっている型
  - 前者はIntやString、後者はMaybe Charなど
- Nothingの型がMaybe aであることに注意
  - Maybe aのaがあるので多相的とのこと。多相的って何？

```
ghci> Just 3 :: Maybe Int
Just 3
ghci> Just "Haha"
Just "Haha"
ghci> Just 84
Just 84
ghci> :t Just "Haha"
Just "Haha" :: Maybe String
ghci> :t Just 84
Just 84 :: Num a => Maybe a
ghci> :t Nothing
Nothing :: Maybe a
ghci> Just 10 :: Maybe Double
Just 10.0
```

## 多相的（polymorphic）とは

- 1つの値や関数が、複数の型として振る舞えること
  - poly（多くの）+ morph（形）が語源
  - 型の中に型変数が残っていれば多相的
- `Nothing :: Maybe a` の `a` はまだ決まっていないので、同じ`Nothing`が`Maybe Int`にも`Maybe String`にもなれる
  - 「Nothingが型ごとに何種類もある」のではなく、1つのNothingが多くの形を取れる
- `length :: [a] -> Int` も多相的
  - 中身を見ずに個数を数えるだけなので、`a`が何であってもリストでさえあればよい
- 逆に`Just 'a' :: Maybe Char` は`a`が`Char`で埋まっているので多相的ではない（具体型）

```
ghci> Nothing :: Maybe Int
Nothing
ghci> Nothing :: Maybe String
Nothing
ghci> Nothing :: Maybe (Maybe Bool)
Nothing
```

### 多相には2種類ある

- パラメータ多相：制約なしの型変数
  - `Nothing :: Maybe a`。中身の値を1つも持たないので`a`に何の要求もなく、制約が付かない
- アドホック多相（型クラスによる多相）：制約付きの型変数
  - `Just 84 :: Num a => Maybe a`。「`Num`のインスタンスである型なら何でも」に限定される

### 制約は「中身」から外側に伝わる

- 数値リテラル`84`自体がすでに多相的。`:t 84` は `Num a => a`
  - 内部的には`fromInteger 84`に展開されている。だから`Int`にも`Double`にもなれる
- その`84`を`Just`で包むと、制約もそのまま外側に引き継がれる

```
84      :: Num a => a
Just 84 :: Num a => Maybe a
```

- `Just 84 :: Maybe Double` が通るのは、`84`の型がまだ確定しておらず`Double`を選べるから
- `Just "Haha" :: Maybe Double` がエラーになるのは、文字列リテラルが最初から`String`に確定していて、`String`は`Num`のインスタンスではないから
- つまり Maybe が持つ制約は、中に入れた値の制約がそのまま外に出てきたもの

## 具体型（concrete type）の補足

- 具体型かどうかの判定は「型変数が残っていないか」で見るとわかりやすい
  - `Int`、`String`、`Maybe Char`、`[Int]` → 型変数なし → 具体型
  - `Maybe a`、`[a]`、`Num a => Maybe a` → `a`が残っている → 具体型ではない（多相型）
- 「具体型 ⇔ 多相型」は「型変数が全部埋まっているか ⇔ まだ残っているか」の裏表の関係
  - 多相型は、たくさんの具体型を生み出せるテンプレートのようなもの
  - `Maybe a`というテンプレートから`Maybe Int`・`Maybe String`…という具体型が作られる
- `Maybe`単体は型ですらない（型コンストラクタ）。`Maybe Int`まで書いて初めて具体型になる
  - 同じく`[]`単体も型ではなく、`[Int]`で具体型
- 値が実際に使われる場面では、型変数は最終的に必ず具体型に埋まる
  - `Nothing`の型は`Maybe a`だが、実際にプログラムの中で使うときは文脈から`a`が`Int`などに決まる
  - 多相のまま実行されるわけではなく、コンパイル時に具体型が確定する
