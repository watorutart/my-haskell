# Haskell学びメモ 20260903

- 型シノニム：型同義名
  - [Char]とStringが同値で交換可能なこと、これが型シノニム
  - 何かするわけではなく、可読性が高くなるだけ
- Stringはこんな感じになってる
  - typeと言ってるものの新たな型を作ってる訳ではない

```
type String = [Char]
```

英文字列を全部大文字に変える関数 toUpperString を作るとしたら、その型宣言はこうできる

```
toUpperString :: [Char] -> [Char]
----
toUpperString :: String -> String
```

- 前にData.Mapを使った時に連想リストからMapに変換した

```
phoneBook :: [(String, String)]
phoneBook = [("betty"), "555-2938"], ... ]
----
```

- phoneBookの型は[(String, String)]です。この型にさらに有益な情報を型シノニムで載せる
- Stringのシノニムも作る
  - → 自分のプログラムの中で使っている文字列について「ただの文字列じゃなくて実際はこれを表してるんだよ」という情報を伝えたい時、Stringに型シノニムを与える
  - 型として別名を与える、みたいなことかな？

```
type PhoneBook = [(String, String)]
type PhoneNumber = String
type Name = String
type PhoneBook = [(Name, PhoneNumber)]
```

- これを使うと関数もいい感じに書ける
- 確かに使わないバージョンは何やってんのか定義だけだとよくわからんね。
  - というかあれか、カリー化してるからこそでもある？普通の関数では並列に引数名と並ぶけど、Haskellは型の流れを書くからあるのかな？

```
inPhoneBook :: Name -> PhoneNumber -> PhoneBook -> Bool
inPhoneBook name pnumber pbook = (name, pnumber) `elem` pbook

-- 型シノニムを使わないと...？
inPhoneBook :: String -> String -> [(String, String)] -> Bool
```
