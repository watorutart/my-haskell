- リスト内包表記でもパターンマッチが使用可能
  - タプルのリストをa+bで処理するって感じか
  - は〜なるほど。パターンマッチングの話だから値を指定すれば一部だけ処理できるんだ
- 空リスト[], :を含むパターンと合致させることができる。
  - x:xsはリストの先頭要素をxに束縛し、リストの残りをxsに束縛します。
    - → あったなそんなの。先頭要素だけ:で簡単に追加できるんだよな
    - Haskellプログラマはx:xsというパターンを、特に再帰関数と一緒によく使う。ただし:は長さが1以上のリストに対してしか合致しない

```
ghci> let xs = [(1,3), (4,3), (2,4), (5,3), (5,6), (3,1)]
ghci> [a+b | (a, b) <- xs]
[4,7,6,8,11,4]
ghci> [x*100+3 | (x, 3) <- xs]
[103,403,503]
```

- head'関数の定義にあるように、複数の変数に束縛したいときは丸括弧で囲まないと構文エラーになる
- error関数は文字列を引数に受け取り、その文字列を使ってランタイムエラーを生成する
  - 基本的にはプログラムをクラッシュさせるものなのでみだりに使うのはNG

```
head' :: [a] -> a
head' [] = error "Can't call head on an empty list, dummy!"
head' (x:_) = x
```

- tellは空・単一・２要素のリストにももっと多くの要素にも合致するので安全に使える。あらゆる長さのリストをどう扱えば良いかわかっているので

ghci> tell [1]

- 注意点として、パターンマッチでは++演算子（2つのリストを繋げる演算子）が使えない。
  - 例えばパターン(xs ++ ys)に対して合致させようにもリストのどの部分とどの部分を合致させるかHaskellに伝えようがない。
  - (xs ++ [x,y,z])や(xs ++ [x])というパターンなら、リストの性質から合致できそうだが、実際にはできない。

結論から言うと、Haskellのパターンマッチは「データがどういう構造で作られているか（コンストラクタ）」を上から順番にチェックする機能だからです。

仕組みをバラすと「なるほどな」と納得できると思うので、分かりやすく解説しますね。

そもそもリストはどう作られている？
Haskellのリスト（例えば [1, 2, 3]）は、裏側では ++ ではなく、:（コロン / cons演算子）というコンストラクタを使って、以下のように作られています。

Haskell
1 : (2 : (3 : []))
「先頭の要素」と「残りのリスト」を右へ右へと繋いでいく構造（単方向連結リスト）になっています。

そのため、Haskellがパターンマッチをするときは、「先頭から順番に箱を開けていく」ことしかできません。

(x : xs) というパターンなら、「先頭の1個（x）」と「残り全部（xs）」に綺麗に分解できるので、Haskellも迷わずマッチングできます。

なぜ (xs ++ ys) がダメなのか？
(xs ++ ys) というのは、言わば「途中にあるかもしれない切れ目」を探す行為です。

例えば、[1, 2, 3, 4] というリストに対して (xs ++ ys) をやろうとすると、Haskellはパニックになります。

xs が [] で、ys が [1,2,3,4] ？

xs が [1] で、ys が [2,3,4] ？

xs が [1,2] で、ys が [3,4] ？

このように「分け方の選択肢が何通りもある」ため、Haskellはどれを選べばいいか一意に決められず、エラーにしてしまいます。

じゃあ、なぜ (xs ++ [x]) もダメなの？
(xs ++ [x,y,z])や(xs ++ [x])というパターンなら、リストの性質から合致できそうだが、実際にはできない。

「後ろの1個（[x]）って決まってるんだから、引き算すれば xs も分かるでしょ！」って思いますよね。人間なら「お尻から見れば一発じゃん」と分かります。

しかし、前述の通りHaskellのリストは先頭からしか辿れない構造です。

もし (xs ++ [x]) を許してしまうと、Haskellは結局、「先頭から最後まで全件スキャンして、最後の1個の手前がどこかを突き止める」という重い計算（関数処理）を裏で走らせなければならなくなります。

パターンマッチの鉄則
Haskellのパターンマッチは、あくまで「データの見た目（構造）をチェックするだけ」の超高速な機能です。

できること： (x:xs) ＝「先頭に要素があって、後ろにリストが続いてるね」（一瞬で判断できる）

できないこと： (xs ++ [x]) ＝「最後までループを回して、お尻の1個を切り出す処理をしてね」（計算が必要になる）

パターンマッチの皮をかぶって裏で重い計算（関数）を動かすことはさせない、というHaskellの設計思想（言語のルール）があるため、これも禁止されています。

💡 どうしても後ろの要素をマッチングしたい時は？
もし「リストの最後の要素」を使って何か処理したい場合は、パターンマッチではなく、リストをひっくり返す reverse 関数などを使って工夫するのが一般的です。

Haskell
-- リストをひっくり返せば、欲しかった「お尻の要素」が「先頭」に来る！
case reverse myList of
    (x : xs) -> -- x が元々のお尻の要素、xs が残りの部分（逆順）
    []       -> -- 空リストの場合
「リストは先頭からしか触れない一本道」というイメージを持つと、Haskellの動きがかなりスッキリ理解できるようになりますよ！
