# Haskell学びメモ 20260610

- リスト内包表記の中のletを述語のように使っているが、リストをフィルタしてるのではなく名前を束縛している。
- letで定義された名前は、出力とそのletより後ろのリスト内包表記の全てから見える
  - これを使うと下記のように条件に当てはまるBMIのみを返すように関数を変えられる
- リスト内包表記の`(w, h) <- xs`の部分はジェネレータと呼ばれる。
  - letの束縛よりも前に定義されているので、変数bmiはジェネレータからは参照できない。

```
calcBmis :: [(Double, Double)] -> [Double]
-- calcBmis xs = [bmi | (w, h) <- xs, let bmi = w / h ^ 2]
calcBmis xs = [bmi | (w, h) <- xs, let bmi = w / h ^ 2, bmi > 25.0]
```

- GHCiで直接関数や定数を定義するときは、let式のinの部分を省略できる。省略した場合、定義した名前はそれ以降の対話的なセッション全体から見えるようになる
- 最初の行ではinの部分を省略したのでGHCiはこの行ではzootを使わないと理解し、以降のセッションのためにzootを覚えておく
- 2つ目のlet式はinパートを含んでいて、bootに引数を渡して呼んでいます。
  - in部分が省略されていないlet式はそれ自体が値を表す式なのでGHCiはその値を表示した。
  - なので、以降でbootを使おうとするとscope外のためエラーが出たっぽい

```
ghci> let zoot x y z = x * y + z
ghci> zoot 3 9 2
29
ghci> let boot x y z = x * y + z in boot 3 4 2
14
ghci> boot

<interactive>:14:1: error: [GHC-88464]
    Variable not in scope: boot
    Suggested fix: Perhaps use ‘zoot’ (line 11)
```
