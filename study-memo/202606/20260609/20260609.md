# Haskell学びメモ 20260609

- let式：どこでも変数を束縛でき、let自身も式になる。しかし、let式が作る束縛は局所的で、ガード間で共有されない。パターンマッチは使える
  - let式は、let bindings in expressionという形をとる。letで定義した変数はそのlet式全体から見える
    - つまり、whereはガード全体から見れたけど、letはletの中だけのスコープってことか？
    - let式はコード中のほとんどどんな場所でも使える
  - どゆこと？？？

```
ghci> 4 * (let a = 9 in a + 1) + 2
42
ghci> [let square x = x * x in (square 5, square 3, square 2)]
[(25,9,4)]
```

- letではセミコロン区切りを使える

```
ghci> (let a = 100; b = 200; c = 300 in a*b*c, let foo = "Hey "; bar = "there!" in foo ++ bar)
(6000000,"Hey there!")
```

- letとパターンマッチがあればタプルを要素に分解してそれぞれ名前に束縛可能

```
ghci> (let (a, b, c) = (1, 2, 3) in a+b+c) * 100
600
```

- let式はリスト内包表記の中でも使える
- letは使い勝手が良いものの、スコープが局所的なのでガードを跨いでつかない。
- 後ろで部品を定義するのが好きだからwhereを使うという人もいる。その方が関数の本体が名前と型宣言に近くなるので、コードが読みやすくなr。
