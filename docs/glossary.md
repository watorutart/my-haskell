# 用語集

Haskell学習中に出てきた用語や概念をまとめる。

| 用語 | 説明 |
| --- | --- |
| 高階型 (higher-kinded types) | 型コンストラクタ自体を型変数として扱う型システムの機能。<br>`foldl :: Foldable t => (b -> a -> b) -> b -> t a -> b` の `t` がこれにあたる。<br>- `a`: 中身の要素の型（TSのジェネリック `T` と同じ感覚）<br>- `t`: `Array`・`Map`・`Maybe` のような「容れ物」自体を抽象化した型変数（TSのジェネリクスでは表現できない）<br>- `t a`: 「`t` という容れ物に `a` 型の要素が入っている」状態を表す具体的な型<br><br>TSのジェネリクスは型（種類 `*`）しか変数にできないが、Haskellの `t` は型を作るもの（種類 `* -> *`）自体を変数にできる。これにより `foldl` は「リストに限らず `Foldable` を満たすどんな容れ物にも使える」という抽象化ができている。 |
| カリー化 (currying) | Haskellの関数に「多引数関数」という特別な種類はなく、実体は1引数関数の連鎖。<br>`foldl :: (b -> a -> b) -> b -> t a -> b` は見た目上3引数だが、実際は `(b -> a -> b) -> (b -> (t a -> b))` という1引数関数が1引数関数を返す連鎖。<br>「部分適用」とは、この連鎖の途中(全部より少ない数)まで引数を渡して止まっている状態を指すだけで、部分適用によって特別な種類の関数ができるわけではない。元の関数も部分適用の結果も構造上は同じ「1引数関数」。 |
| 点なしスタイル (point-free style) / イータ簡約 (eta reduction) | 関数定義の末尾の引数を省略して書けるカリー化の性質。<br>`foo a = bar b a` という定義は、どんな `a` を渡しても両辺が常に一致する。`bar b` の時点ですでに「`a` を受け取って結果を返す関数」として完成しているため、両辺から `a` を消して `foo = bar b` と書ける。<br>例: `addFive x = (+) 5 x` → `addFive = (+) 5`<br>例: `sum' xs = foldl (+) 0 xs` → `sum' = foldl (+) 0`<br>引数を書かずに関数合成だけで定義を組み立てるこのスタイルを「点なしスタイル」と呼ぶ。 |
| アナロジー (analogy) | 型は違う2つの物事の間に「関係の形が同じ」という類似点を見出すこと。比例式 `A:B :: C:D`（AとBの関係は、CとDの関係と同じ）の形で表せる。<br>例: `foldl:foldl1 :: scanl:scanl1`。`foldl`から`foldl1`への変化（初期値の引数が消え、リストの先頭要素がseedになり、空リストがエラーになる）と、`scanl`から`scanl1`への変化が全く同じパターンになっている。 |
| 等式推論 (equational reasoning) | 関数の定義を「いつでも両辺を置き換えてよい等式」とみなし、式をその定義に沿って一歩ずつ変形していく手法。中学数学の代入計算と同じ発想をコードに適用する。<br>例: `double x = x + x`、`inc x = x + 1` のとき `double (inc 3)` を評価すると<br>`double (inc 3)` → `double (3 + 1)` → `double 4` → `4 + 4` → `8`<br>のように、実行せずノート上で変形だけで答えを出せる。<br>これが成り立つのは「参照透過性」（同じ入力なら常に同じ結果を返し、外部の状態を書き換える副作用がない）があるから。副作用がある言語では式を結果に単純置換できず、この変形は崩れる。<br>用途は2つ：(1) 人間が「処理Aと処理Bは等式変形で一致する」と証明できれば、テストなしでも安心してリファクタリングできる。(2) コンパイラも同じ推論を使って `reverse (reverse xs)` のような式を効率的な形に自動変形（最適化）する。<br>本質は「関数（名前）とそのロジック（中身）は常に相互に置き換え可能」であること。この双方向の置き換えを繰り返しても、プログラムの正しさは変わらない。 |
| Kan拡張 (Kan extension) | 圏 A 上で定義された関手 F:A→C を、より広い圏 B（A から関手 K:A→B で埋め込まれる）へと「もっとも自然に」引き延ばす操作。<br>A →(K)→ B、A →(F)→ C という状況で、K を経由すると元の F になるべく近くなるような関手 X:B→C を探す。<br>近づけ方の向きによって2種類ある：<br>- 左Kan拡張 (Lan_K F)：F→X∘K の向きの自然変換。下から押し上げるように広げる<br>- 右Kan拡張 (Ran_K F)：X∘K→F の向きの自然変換。上から抑え込むように広げる<br>「広い定義域」とは集合としての要素数の広さだけでなく、対象（オブジェクト）の数と射（モルフィズム＝関係性）の豊かさの両方を含む。<br>例: `Int→Float`（要素が増えるケース）、3点の集合→3点+対称性を持つ構造（要素数は同じで射だけ増えるケース）、どちらも「広い」に含まれる。<br>極限・余極限、随伴関手など圏論の主要概念の特殊ケースとして表現でき、マックレーンは「すべての概念はKan拡張である」と評した。 |
| The Elm Architecture (TEA) | Model・Msg・View・Updateの4要素が一方向にループしてUIを構成するアーキテクチャ。<br>- Model: アプリの状態を表す型<br>- Msg: 起こりうるイベントの種類を表す型（例: `type Msg = Increment | Decrement`）。発生源はユーザー操作だけでなく、HTTPレスポンスやタイマーなど外部の非同期イベントも含む<br>- View: `Model -> Html Msg` の純粋関数。ModelからUIを描画し、そこにMsgを発行するハンドラを埋め込む<br>- Update: `Msg -> Model -> Model` の純粋関数。発行されたMsgと現在のModelから新しいModelを計算する<br><br>循環の流れ: `Model → View → (ユーザー操作/外部イベントでMsg発行) → Update → 新Model → View ...`<br>View・Updateがともに副作用のない純粋関数であるため、この循環全体が等式推論しやすく、状態遷移を予測・テストしやすい。 |
| take | リストの先頭からN個の要素を取り出す関数。`take :: Int -> [a] -> [a]`。<br>Haskellは遅延評価なので `take 5 [1..]` のように無限リストに対しても使え、指定した個数を取り出した時点で計算を打ち切る（無限リスト全体を評価しようとはしない）。 |
| 等差数列の範囲構文（`[a..]` / `[a,b..]`） | `enumFrom` の糖衣構文。`[1..]` は「1から始まり+1ずつ増えていく無限リスト」を表し、`repeat 1`（同じ値1をずっと繰り返すリスト）とは全くの別物。<br>`[1,3..]` のように2つ値を書くと差分（ステップ）を指定できる: `[1,3..10]` → `[1,3,5,7,9]`。 |
| 正格 (strict) / 正格評価 | 計算を先延ばしにせず、その場ですぐに評価すること。多くの言語ではデフォルトの評価方式なので特に意識されないが、Haskellは遅延評価がデフォルトのため、あえて即座に評価させたいときに「正格」という概念がわざわざ際立って登場する。<br>例: `foldl` は各ステップのアキュムレータ計算（`0+1`など）を評価せず未評価の式（サンク）として先延ばしにするため、大きなリストでサンクが積み上がりスタックオーバーフローを起こしうる。`foldl'`（正格な左畳み込み）はステップごとにアキュムレータを即座に評価するため、サンクが溜まらない。 |
| 多相的 (polymorphic) | 1つの値や関数が、複数の型として振る舞えること。poly（多くの）+ morph（形）が語源。型に**型変数**が含まれていれば多相的。<br>例: `Nothing :: Maybe a` の `a` はまだ何の型か決まっていないため、同じ `Nothing` という値が `Maybe Int` にも `Maybe String` にもなれる。`length :: [a] -> Int` も、中身を見ずに個数を数えるだけで `a` が何であってもよいので多相的。<br>対して `Just 'a' :: Maybe Char` は `a` が `Char` に埋まっているので具体型であり、多相的ではない。<br><br>**2種類の多相**<br>- パラメータ多相: 制約なしの型変数。`Nothing :: Maybe a` は中身の値を1つも持たないため `a` に何の要求もなく、制約が付かない<br>- アドホック多相（型クラスによる多相）: 制約付きの型変数。`Just 84 :: Num a => Maybe a` は「`Num` のインスタンスである型なら何でも」に限定される<br><br>**制約は中身から伝わる**<br>数値リテラル `84` 自体がすでに多相的（`84 :: Num a => a`、内部的には `fromInteger 84`）なので、`Just` で包むと制約もそのまま外側に引き継がれる。<br>`Just 84 :: Maybe Double` が通るのは `84` の型がまだ確定しておらず `Double` を選べるから。`Just "Haha" :: Maybe Double` がエラーになるのは、文字列リテラルが最初から `String` に確定しており、`String` は `Num` のインスタンスではないから。 |
| モジュール検索パス (module search path) | GHC/GHCiが `import Geometry.Sphere` のようなインポート文を解決するとき、モジュール名のドットを `/` に置き換えて `Geometry/Sphere.hs` というファイルパスを作り、それを検索パス（`-i` で指定。既定値は起動時のカレントディレクトリ `.` のみ）に含まれる各ディレクトリの直下から探す。<br>**importしている側のファイル自身の場所は一切考慮されない**。JS/Pythonの相対import（`./foo`）のような「このファイルから見て」という解決方法はGHCにはなく、あくまで検索パス基準でモジュール名をファイルパスへ機械的に変換するだけ。<br>そのため、リポジトリのルートでghciを起動して `:l study-memo/xxx/Main.hs` のように離れた場所のファイルを読み込むと、検索パスはルートのままなので同じ相対位置にある `Geometry/Sphere.hs` を見つけられずエラーになる。`:cd` でモジュールが置かれたディレクトリへ移動するか、`:set -i<path>` で検索パスを追加する必要がある。 |
